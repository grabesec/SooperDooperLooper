# SDL QA and code improvement pass (2026-10-04)

A QA pass over `main`, run alongside the security audit. The Vault, rollover, identity, audit, OIDC and lockout code was left to the security-fix work, and the lab to the manual QA lab work.

## Results

- **Tests:** 133 passed, 7 skipped. The skips are the Docker integration tests (`SDL_INTEGRATION=1`).
- **Lint and format:** the CI checks (`ruff check`, `ruff format --check`) pass.
- **Stricter lint:** a ruff pass with bugbear, simplify and pylint rules found six style suggestions:
  - Four `try`/`except`/`pass` blocks that should use `contextlib.suppress`. Fixed in PR #6 (merged), with no change in behaviour.
  - The empty `Module.start`/`stop` hooks (`src/sdl/core/module.py`). Left as is on purpose: they are optional no-ops that modules override.
- **Type checking:** mypy reports no issues when run with the project's Python environment.
- **Error handling:** the broad `except Exception` blocks in `api/app.py`, `core/forwarding.py` and `core/orchestrator.py` all log the error or re-raise it, and the run-start handler cleans up its state first. None of them hide failures.

## Outcome

`main` is clean apart from the findings in the security audit. The only code change from this pass was the `contextlib.suppress` cleanup in PR #6.
